# Explain

解释用户提出的问题。同一条消息里没有要求实现，就不要开始改代码。

## 约束

- 不要使用读者必须离开当前回复才能理解的指针：未展开的原则编号、未点名的缩写、找不到先行词的代词。
- 每个指称在当句或紧邻句给出名称和足够上下文。
- 缩写在首次出现时写全称；之后可以使用缩写。
- 代词必须在当前回复里有明确先行词。不要使用悬挂的「它 / 这 / 上述」。
- 引用外部材料时，先用一句话说清它主张什么。链接只作核验，不承担语义。
- 不要只写结果。涉及机制时，在同一次说明里写清条件、动作、结果。
- 不要用比喻代替机制。需要直觉时，先写机制，再标明类比在何处断开。
- 不要把「有逻辑 / 严谨 / 讲清楚」当作可执行约束。
