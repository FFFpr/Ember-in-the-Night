# 像素绘图标准

> **本文件：** HD-2D 下像素 2D 资产的验收标准（画布、色数、色块）。Godot 侧受光 / 投影 / Nearest 仍见 [`art-style.md`](art-style.md)。可运行对照在 [`art_style_demo/07_hd2d/`](../../art_style_demo/07_hd2d/)。

## 结论（先读这个）

**色数与画布面积不是线性正相关。** 在可交付的像素精灵上，独特色数近似随不透明像素数的**平方根**增长。对本仓库 LPC 道具 + `Aseprite-User` 精灵（n=31）拟合：

```text
C ≈ 0.19 √A
```

`C` = 不透明像素上的独特 RGBA 色数，`A` = 不透明像素数。实测带：`C / √A` 的 10–90 分位约为 **0.09–0.38**（中位 0.24）。

只卡色数不够。把 Demo A 插画缩放到 320×180 并量化到 32 色，色数过关，但 **4-连通同色色块** 的碎点比约 0.73、平均色块约 4 像素——看起来仍是缩小的插画，不是像素画。

生产路径：**在 Aseprite 里按本标准直接画（索引色、先剪影后色块）**。不要用「高细节 prompt → 再交给 Aseprite 量化」当交付。HD-2D 的「贵」在 3D 光影与空间，不在精灵里堆纹理。

## 什么是一张好的像素图

同时满足：

1. **剪影可读**：缩小到 50% 或改成纯黑剪影，仍能认出是锤子 / 铁砧 / 人。
2. **色块（cluster）干净**：同色像素聚成面，而不是盐胡椒噪点。这是 *Pixel Logic*（Michael Azzi）里称为 shapes / clusters 的东西。
3. **色数克制**：每个材料一条 3–5 步色斜坡（ramp），高光偏暖、暗部偏冷（色相偏移），不用纯黑描边。
4. **有主次**：只有一处最亮（锻炉、刃面、眼睛），其余降对比。AI 插画常处处是高光。
5. **和别的图同一套尺**：同一层级的角色 / 道具画布一致，脚底锚点一致。

人眼大约一次只能稳住有限个颜色区域（常被通俗说成 7±2）。把 200 色的 32×32 丢给观众，大脑还是会合并成少数几块——只是合并方式不受你控制。

## 可复现的数字门禁

量的是**不透明像素**（alpha ≥ 16）。透明底不计入 `A` 与 `C`。

### 画布

| 层级 | 画布 (px) | 用途 |
|------|-----------|------|
| 图标 / 小道具 | 16×16 或 32×32 | UI、马蹄铁、锭 |
| 手持 / 角色 | **48×48**（角色也可 32×48） | 锤子、主角四向 |
| 场景道具 | 64×48 或 64×64 | 铁砧、桶 |
| 大型道具 | 96×80 | 锻炉立面 |
| 2D 对照画布 | 320×180 | 仅 look-dev；正式 HD-2D 场景是 3D，不画整张像素插画 |

整数倍缩放。不要 24×24 与 32×32 混用同一层级。

### 色数

`C_max = min(表内上限, max(8, round(0.35 √A)))`

| 画布 | 建议上限 | 来源 |
|------|----------|------|
| 16×16 / 16×32 | 8 | 《星露谷》(Stardew Valley) 物件约 6–8 色；NES 习惯 |
| 32×32 / 32×48 | 12–16 | LPC 角色/道具；SNES 角色 |
| 48×48 | 16 | 本仓库锤子实测 8–13 |
| 64×64 | 20 | LPC 锻炉级 |
| 320×180 整幅（仅对照） | **32** | 超过后点阵可读性迅速掉 |

全局调色板先锁一版（建议 Endesga 32 或项目自建「锻夜」板，见实验脚本 `pixel_common.py`），再从中抽每张图的子集。不要每张图临时加「只此一次」的颜色。

### 色块

对**索引色成品**（不要先量化再量插画）：

| 项 | 英雄道具（锤、砧、角色） | 说明 |
|----|--------------------------|------|
| 碎点比 | **≤ 0.30** | 面积 ≤2 的 4-连通色块 / 全部色块 |
| 平均色块 | **≥ 8** px | 过小 = 噪点；过大且全是矩形 = 偷懒 |
| 可读色块数（面积 ≥4） | 大约 `0.8–2.0 × √A` | 随 √A 涨，不随 A 涨 |

`Aseprite-User/export/scenes/workshop_fp/workshop_fp_full.png`（384×256、48 色）碎点比 0.79、平均色块 2.7：这是「色数过关、色块没过关」的反例，不要再复制这条流水线。

## 和参考作的关系

### 《星露谷》(Stardew Valley)

- 角色帧 **16×32**，地砖 **16×16**，立绘 64×64。
- 社区美术指南（Sundrop Art Guide）：多数物件 **6–8 色**，复杂物才破 8；不用纯黑纯白；轮廓用最暗的有色阶。
- ConcernedApe 访谈：把 tile 锁在 16×16 是为了范围可做完，不是因为「更大一定更好」。

### 《歧路旅人》(Octopath Traveler) / HD-2D

- 高桥正志：像素分辨率拉太高会变成「漂亮的画」，只加粗像素又像在补偿怀旧——两边都卖不出「现代全价」。最终是**留住点阵可读性 + 三维空间与光影**。
- Famitsu / Siliconera：一度把分辨率和饱和度推过了，像素的好处消失；角色在大屏幕上显得孤单，于是加密的是**场景 tile 变化和颜色密度**，不是把角色画成照片。
- 社区对过场角色贴图像素尺寸说法不一（截图像素约 18×32，也有 36×36 之说）。对制作更有用的是：**角色保持 16-bit 可读剪影，丰富感交给 3D**。本项目按 48×48 英雄精灵 + `Sprite3D` 进 3D（见 `art-style.md`）。

### LPC Style Guide

虽已不再当项目艺术语言，其操作句仍然有效：先用色块塑体积，线后加；色斜坡必须色相偏移（亮偏黄、暗偏紫）；少抖动或不抖动。

## 文献与教程（不替代本标准）

| 类型 | 文献 | 用它做什么 |
|------|------|------------|
| 论文 | Gerstner et al., *Pixelated Image Abstraction*, NPAR 2012；后续 C&G 2013 | 证明「缩小 + median-cut」不是像素画；要同时优化特征对齐与调色板 |
| 论文 | 后续像素风格生成（如 palette-informed diffusion） | 生成模型必须显式约束调色板与剪影，否则会滑向照片 |
| 书 | *Pixel Logic*（Michael Azzi） | 剪影、色块形状、可读性、清理 |
| 教程 | Lospec / MortMort / hue-shifting ramps；Gas13 *So you want to be a Pixel Artist* | 斜坡与光照；避免枕式阴影 |
| 规范 | [LPC Style Guide](https://lpc.opengameart.org/static/LPC-Style-Guide/build/styleguide.html) | 协作时的块面与色相偏移 |

没有发现「色数 = k × 画布面积」的业界公式。硬件史（NES 每 8×8 块 4 色、PICO-8 全局 16 色）和当代独立游戏是**自愿**把色数压在 √A 量级，因为那才像像素画。

## 实验（Demo A → 两条生产线）

脚本与图：[`art_style_demo/07_hd2d/`](../../art_style_demo/07_hd2d/)。原始表：`experiment/metrics/sprite_metrics.csv`。

| 生产线 | 做法 | 工坊 320×180 | 锤子 48×48 |
|--------|------|----------------|------------|
| A | Demo A / prompt 插画 → 双三次缩放 → k-means 量化（模拟 Aseprite「转索引」） | 32 色，碎点比 **0.73**，平均色块 **4.2** | 10 色，碎点比 0.55 |
| B | 先锁定画布与「锻夜」板，按色块直接画 | 17 色，碎点比 **0.00**，平均色块很大 | 9 色，碎点比 0.00 |

**A 不能当交付**：构图还在，点阵语言没有。这就是「细节过多、重点抓不住」。

**B 的数字对、矩形填充不够**：只画大色块会落到口述 Aseprite 时的偷懒（剪影弱、材料面不够）。门禁要**同时**防 A 的碎点与 B 的空心矩形——剪影检查 + 每材料 3–5 步斜坡是底线，不是可选项。

可运行 HD-2D look-dev（`07_hd2d` 工坊 / 街道）用 B 的精灵进 `Sprite3D`，用 3D 灯、雾、轻微景深补「卖相」。这是《歧路旅人》那条路的最小验证，不是最终美术。

## Aseprite 制作顺序（给资产 issue）

1. 按上表选定画布与 `C_max`，建成**索引色**精灵，打开「只用调色板颜色」。
2. 剪影（1 色）→ 材料块（每材料 1 色）→ 斜坡（3–5 步，色相偏移）→ 极少量点缀。禁止先画灰阶照片再上色当完成。
3. 导出前跑门禁：色数、碎点比、平均色块；再做一次纯黑剪影可读检查。
4. 向 [Aseprite-User](https://github.com/FFFpr/Aseprite-User) 开 issue 时，画布表必须填本文件的画布与 `C_max`，不要只写「像素风」。

测量：

```bash
python3 art_style_demo/07_hd2d/tools/measure_sprites.py
```
